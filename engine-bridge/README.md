# Pinned browser engines

The browser app requires OpenSysML and SysML Toolkit WASM workers. Preparation scripts verify upstream archives, retain licenses and write ignored assets/provenance to `static/vendor/`. Temporary source, toolchains and caches stay under `sandbox/`.

| Engine        | Pin                                                  | Purpose                                                     |
| ------------- | ---------------------------------------------------- | ----------------------------------------------------------- |
| OpenSysML     | 0.12.0 / `760c4d1fc8edfa4e214423099065c0a7c1b24e2d`  | Parsing, model inspection, validation and native evaluation |
| SysML Toolkit | 0.10.10 / `339ef0e073d06e553e81c079755ddfcd224e4b92` | Source transformations and draft language queries           |

`scripts/prepare-opensysml.mjs` verifies the source archive, applies the retained overlays under `engine-bridge/opensysml/`, runs bridge tests and builds with Go 1.27.3. The derived module exposes `studio_evaluate_view_v1`, `studio_relationships_v1`, `studio_exploration_v1` and `studio_render_document_v1`. It records source/archive, overlay, builder, toolchain, binary and runtime identities. Set `SYSML_GO` to a local Go 1.27.3 binary on platforms without the pinned Linux x64 download path.

`scripts/prepare-sysml-toolkit.mjs` verifies its release archive and every prepared asset. It retains the Apache and EPL licenses, library assets, build information and third-party notices. Neither preparation script installs a toolchain globally.

The raw OpenSysML host lives inside a disposable worker. Toolkit owns its own transformation worker and prepared library. A proposal is accepted only after the host validates its complete source set through OpenSysML. Worker inputs/replies are versioned and TypeBox-validated; 60-second timeouts and cancellation terminate each worker. The Toolkit adapter now returns source-bound UTF-8 splices and, for creation, the selected owner's recorded member extent. The workspace verifies replay, source membership and creation scope before preparing layouts and semantic postconditions.

For an engine upgrade, update explicit pins/checksums, review overlay seams, compare diagnostics/identity/view behavior with fixtures, run unit/build/browser checks and record the new generated provenance. Never turn upstream README claims into application capability claims without that evidence. See root NOTICE for retained source origins.

The structural bridge retains engine hierarchy, inherited-port correspondence and exact connection endpoints. It adds explicit declaration directions and reference modifiers by recorded origin, without inferring effective directions from types or conjugation. The assembly sources under `examples/assembly/` are copied into the Go bridge test package and included in preparation's input digest. [Structural contract trace and scope](../docs/architecture/structural-views.md).

Native requirement graphs retain the engine's selected subjects and related context. The local overlay adds declared short names, complete owned documentation bodies, satisfaction assertion/negation flags and direct-versus-type-context ownership by looking up recorded AST origins. It does not split rendered detail text, infer satisfaction from subjects, or change the native graph's nodes, edges or order. Requirement transport validation checks exact correspondence, endpoint membership, exposure classification, polarity and direct ownership before publication. A declared relationship is not an execution result.

`render_document.go` (engine `studio_document.go`) adds `ListDocuments` and `RenderDocument` to the pinned engine, which does not yet serve the upstream `RenderDocument` RPC. It resolves document definitions through `docplan.IsDocumentDefinition`, compiles them with `docplan.Compile`, evaluates them with `docir.EvaluateLinked` over the cached model's runtime and renders Markdown or fragment HTML with `docrender` (`WithoutGraphviz`; Graphviz is unavailable in wasm). Markdown keeps the CLI's Mermaid fences; HTML requests the DOT diagram form (source text, no Graphviz call) because the Mermaid HTML path resolves inline images against `os.Getwd`, which js/wasm does not implement, and the browser replaces every `sysml-diagram` figure with its native renderer or the view evaluation's notice anyway. The request mirrors the upstream protojson field names (`modelHash`, `document`, `form`) so the browser contract survives the swap. The response adds the declared origins of every `data-element` reference and `data-name` content path, and types `docplan`/`docir`/`docrender` failures by stage and kind with their source line. `validated_document.go` (combined `studio_document.go`) refuses revisions with validation errors before planning, as the view bridge does; its tests cover HTML, Markdown, unknown documents, non-documents, typed planning errors and the validation gate. The overlay does not change upstream planning, evaluation or rendering semantics.

`insertMember` supports typed part and connection creation. Creation may insert within the recorded owner or promote only its terminal semicolon to a body; existing surrounding source is retained. Toolkit accepts some directionally incompatible connections, so the workspace separately checks explicit out/inout-to-in/inout direction, identical resolved type and exact evaluated usage/port endpoints. Conjugated or ambiguous endpoint paths remain unavailable for graphical creation. [Authoring scope and evidence](../docs/architecture/graphical-authoring.md).

Toolkit also supplies completion, hover, definition, references and formatting queries through a separate disposable language worker. Queries use the complete draft source set, negotiate UTF-16 positions and normalize only supported results. The workbench rejects stale replies; completion and formatting edits remain unapplied draft changes until the normal source transaction validates them. Engine pins, prepared assets and provenance are unchanged. See [source assistance](../docs/architecture/source-assistance-recovery.md).

Read-only `Explore` uses the same validated applied-source revision as named-view evaluation, selects project-owned roots or one exact project declaration, and calls native `RenderExposed`. Project/package scopes support trees; explicit part definitions/usages additionally support bounded structural rendering. Its separate envelope carries the request instead of an authored view identity; it does not write source or saved presentation keys.

Structural attribute compartments retain exact source slices for effective non-library attribute members through the pinned semantic model's `MembersOf` contract. They expose declarations rather than evaluated values. Native action/state artifacts are rendered by the workbench with existing correspondence and bounded graph validation; this adds no execution API or upstream pin change.

The 0.12 port normalizes native optional labels, anonymous names and empty graph arrays to the existing browser contract. Temporary exploration retains explicit ownership; interconnection attributes retain the app's source-backed compartments. `EvaluateRelationships` also returns source-bound requirement rows and satisfaction assertion/negation for the read-only table/matrix. See [compatibility evidence](../docs/research/opensysml-0.12-compatibility.md) and [requirements data](../docs/architecture/requirements-data.md).

Authored interconnection normalization retains native inherited structural occurrences with complete declaration/usage correspondence, while reserving legacy node/port IDs for unchanged saved presentations. Tree and temporary exploration filtering remain unchanged. Native depth/recursion bounds, attribute compartments and explicit connector-selection policy are retained. The combined Go regressions cover exact occurrence semantics, legacy identities and unchanged exploration output.
