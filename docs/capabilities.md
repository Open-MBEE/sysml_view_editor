# Capabilities and known limits

This catalogue describes the current implementation. Check `docs/verification.md` for checks actually performed; a feature description alone is not test evidence.

| Workflow             | Support                                                                                                                                                       | Limit                                                                                                                                                                                                                  |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Project sources      | Multiple imported SysML files resolve together                                                                                                                | 20 files / 5 MiB per source set; one active source editor                                                                                                                                                              |
| Source editing       | Drafts, apply/discard, source undo/redo and bounded layout retention                                                                                          | Native text area; language assistance remains future work; unsafe declaration/context matches lose affected positions                                                                                                  |
| Named views          | Open declarations; create GeneralView/InterconnectionView usages in a package                                                                                 | Custom filters/definitions remain editable in source                                                                                                                                                                   |
| Diagram rendering    | Flat tree views; nested interconnection parts, typed inherited ports, explicit directions and resolved port endpoints through React Flow/ELK                  | Owned-port boundary notation, effective conjugated directions, modeled layout/routes and behavior/sequence/geometry renderers remain future work                                                                       |
| Semantic editing     | Reviewed part definition/usage rename, native view creation, typed part creation and directed same-type port connections                                      | Simple identifiers and qualified names; explicit out/inout to in/inout with identical resolved types; conjugated, ambiguous or undirected endpoints, reconnect, delete, duplicate and behavior editing are unavailable |
| Model navigation     | Expandable ownership tree, declared members, type/kind labels, keyboard navigation and diagram-selection reveal                                               | View declarations use the separate Views list; inherited members are not cloned beneath usages; no full-model search or virtualized rendering                                                                          |
| Source navigation    | Recorded origin range from diagram/port selection; Inspector distinguishes inherited-port usage contexts                                                      | Explorer-only selection does not yet resolve a source range                                                                                                                                                            |
| Diagram presentation | Move nested groups, retain descendant positions, reconcile compatible positions across reviewed edits and bounded source changes, save/reopen and refit panes | Changed bindings, headers, owners or ambiguous correspondence invalidate affected positions; manual overlap avoidance, parent resizing, camera persistence, route edits and independent layout undo remain future work |
| Workbench panels     | Resizable Explorer, Inspector, source/diagram split and Issues; collapse/restore, keyboard and button resizing, reset and browser layout preferences          | Full docking/floating windows are unavailable; preferences do not recover source work                                                                                                                                  |
| Save/reopen          | One version-1 bundle includes source, drafts and positions                                                                                                    | No automatic recovery, active-tab/camera persistence or folder write-back                                                                                                                                              |
| Runtime validation   | TypeBox project/command/message/engine schemas                                                                                                                | Schema validity is separate from SysML semantic validity                                                                                                                                                               |
| Appearance           | Shared shadcn/Radix controls; Light/Dark/System, six palettes and custom muted package/part fills                                                             | Browser preferences, separate from project files; detailed port controls and full old-UI parity remain future work                                                                                                     |
| Execution            | No simulation controls                                                                                                                                        | Rendered behavior or declared verify links would not imply execution results                                                                                                                                           |

The previous app remains the reference for features to evaluate and reintroduce through complete vertical slices. This repository does not claim full SysML v2 language, notation, execution or interchange conformance.

Use **New part** and **Connect ports** in a diagram, or the corresponding Inspector actions, to review source-backed creation commands. Part creation chooses an explicit source owner and existing definition; connections choose actual usage-qualified endpoints. Toolkit supplies source edits, OpenSysML validates the complete candidate, and the workspace checks ownership, bindings and exact connection endpoints before accepting one transaction. New symbols receive automatic layout; source exposure still determines whether they appear in an open view.

Layout reconciliation checks every saved view, including inactive views. Verified commands use source-bound UTF-8 splices; free-form edits use conservative replacement ranges and require unchanged engine-recorded declaration headers, complete usage contexts and compatible resolved bindings. Unknown or ambiguous mappings are invalidated explicitly. This is bounded preservation, not a general persistent-identity guarantee. See [the implemented policy](architecture/identity-reconciliation.md) and [authoring contracts](architecture/graphical-authoring.md).

The startup project is [Smart air workshop](../examples/air-compressor/README.md): nine source files and fourteen named views, opening its pneumatic assembly in Diagram mode. Six views render partial structural/definition/tree representations; eight behavior/sequence/geometry views evaluate but report unavailable renderers. The simpler Workshop remains a separate example.

The [visualization example library](../examples/README.md) records representative models, named views, intended visual quality and current gaps. Its checks distinguish successful engine evaluation from application rendering; use-case, package-graph and other unsupported renderer fixtures remain explicit development targets.
