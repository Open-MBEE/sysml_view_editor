# Engine identity source findings

Recorded 2026-10-26 for the identity/layout investigation. This note records the original source inspection at `fd54b67`; runtime comparisons and implemented reconciliation supply separate evidence. The current production policy is documented in [identity reconciliation](identity-reconciliation.md). The inspected engines are OpenSysML `0.10.0` at `08ef397841767b829e492bbecf6d723483b4421e` and SysML Toolkit `0.10.10` at `339ef0e073d06e553e81c079755ddfcd224e4b92`. The [engine preparation guide](../../engine-bridge/README.md) and preparation scripts own those pins and generated provenance.

## The application has several different identity domains

| Value                                 | What the inspected source defines                                                                                                         | Consequence for matching revisions                                                                                                                                                       |
| ------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| OpenSysML `modelHash`                 | SHA-256 of conformance mode, document count and each ordered document's name, language and full content                                   | Identifies the complete parser input. Comments, filenames, document order and unrelated file changes can change it. It is not an element identity.                                       |
| Normalized model element `id`         | `GetSymbol` returns the symbol's fully qualified name; the worker copies it into the model record                                         | Renaming an element or its owner changes this name. Reusing the name can identify a different declaration.                                                                               |
| Evaluated `correspondence.subject.id` | The bridge formats a located declaration as `file@offset:length`                                                                          | Identifies a recorded source span within a revision. Insertion, replacement, file moves and changes inside enclosing declarations can change it. A same-length replacement can reuse it. |
| Evaluated `correspondence.context`    | The bridge collects ancestor declaration origins and appends the node's origin; inherited-port correspondence adds its declaration origin | Distinguishes occurrences of the same inherited port in a particular usage chain within a view. The origin keys remain sensitive to source edits.                                        |
| Diagram node/port `symbol`            | A renderer traversal counter (`n0`, `n1`, …), with port ordinal appended to the node ID                                                   | Identifies an artifact entry in that rendering. A new traversal can assign the same string to a different element.                                                                       |
| Toolkit `idMap`                       | An edit result's old/new IDs in Toolkit's own session; its public element APIs also expose interchange IDs                                | The inspected application does not expose a mapping from these IDs to OpenSysML origins, model names or diagram symbols. A join must be demonstrated rather than assumed.                |

Sources for the hash and model names are the pinned upstream [parser input key](https://github.com/Open-MBEE/OpenSysML/blob/08ef397841767b829e492bbecf6d723483b4421e/internal/frontend/engine/engine.go#L527), [hash function](https://github.com/Open-MBEE/OpenSysML/blob/08ef397841767b829e492bbecf6d723483b4421e/internal/frontend/engine/engine.go#L1035), [GetSymbol lookup](https://github.com/Open-MBEE/OpenSysML/blob/08ef397841767b829e492bbecf6d723483b4421e/internal/frontend/core/core.go#L335) and [symbol facts](https://github.com/Open-MBEE/OpenSysML/blob/08ef397841767b829e492bbecf6d723483b4421e/internal/frontend/symbolfacts/facts.go#L110). The worker preserves `symbol.id`, ownership and resolved type IDs in [semantic.worker.ts](../../src/lib/engines/opensysml/semantic.worker.ts#L96).

The retained bridge defines [subject/origin fields](../../engine-bridge/opensysml/evaluate_view.go#L18), [origin lookup and subject construction](../../engine-bridge/opensysml/evaluate_view.go#L88), [usage-context construction](../../engine-bridge/opensysml/evaluate_view.go#L149) and [origin-key spelling](../../engine-bridge/opensysml/evaluate_view.go#L209). `QualifiedName` is looked up using a source origin; it is not a persistent ID assigned by this bridge.

The upstream renderer [starts a new structural counter for a rendering](https://github.com/Open-MBEE/OpenSysML/blob/08ef397841767b829e492bbecf6d723483b4421e/internal/ir/view/interconnection.go#L20), [allocates IDs while visiting features](https://github.com/Open-MBEE/OpenSysML/blob/08ef397841767b829e492bbecf6d723483b4421e/internal/ir/view/interconnection.go#L111), [emits counter names](https://github.com/Open-MBEE/OpenSysML/blob/08ef397841767b829e492bbecf6d723483b4421e/internal/ir/view/view.go#L769) and [names ports by ordinal](https://github.com/Open-MBEE/OpenSysML/blob/08ef397841767b829e492bbecf6d723483b4421e/internal/ir/view/behavior.go#L820). Therefore stability observed in one fixture must not be promoted to a guarantee that those IDs persist across edits or views.

The cached upstream sources were inspected under `sandbox/opensysml-build/source/` with the paths shown in those immutable links. That directory is ignored and reconstructed by preparation. Bridge overlays are retained separately in this repository; they are not claimed to exist in upstream source at that commit.

## Toolkit edit evidence at the original investigation revision

The prepared Toolkit JavaScript wrapper documents `checkEdit` as a dry run of splice, reparse, rebuild and reference checks, returning `wouldCommit`, `idMap`, findings and splices. It documents successful `edit` as rebuilding the session, invalidating outstanding handles, and returning old/new ID pairs plus splices in **pre-commit byte offsets per unit**. These descriptions were inspected at generated `static/vendor/sysml-toolkit/sysmlv2.js:465–476` and `:746–763`. The prepared wrapper's SHA-256 is `3c4d015fdce693a103c5a3d6c880c5d930a72bb6fb8cd54ce638abc38aaab52b`, recorded in its generated provenance and verified by [Toolkit preparation](../../scripts/prepare-sysml-toolkit.mjs). Its `elementById`/`elementId` APIs describe interchange UUIDs at `:787–805`; this does not prove that any such UUID is an OpenSysML ID.

At `fd54b67`, the transformation worker checked refusal/findings and returned only full sources; its interface was `Promise<readonly SourceDocument[]>`. The current [transformation result](../../src/lib/workspace/editing/evidence.ts) now includes validated source-bound splices and optional owner extent. The [adapter](../../src/lib/engines/toolkit/transform.worker.ts) still does not treat Toolkit UUID maps as OpenSysML identity. The semantic worker reparses source in a new disposable worker for each request; [worker lifetime](../../src/lib/engines/workers/request.ts#L1) terminates the worker on completion. The application cannot rely on retaining an engine session's in-memory handles across these operations.

Source inspection establishes an available direction for a rename investigation: capture the actual edit report, associate each splice unit with a filename, replay the byte splices against the exact before sources, and compare the result with the returned after sources. The resulting offset relation can then be checked against both versions of the OpenSysML origins. This is a proposed use of the evidence; these sources alone do not establish that every declaration or context can be reconciled.

JavaScript string offsets count UTF-16 code units, so using them directly for the wrapper's documented byte positions would be unsafe for Unicode source. Any adapter must prove UTF-8 byte handling, offset bounds, unit/file association, nonoverlapping splice replay and the exact before/after source binding before publishing correspondence.

## Requirements implied by these contracts

These are deductions from the inspected contracts, not a claim that reconciliation is implemented:

1. Keep model revision, view identity, declaration identity, usage chain and artifact symbol distinct. The same inherited-port declaration appears under multiple usage chains; declaration-only matching can attach the right port to the wrong instance.
2. Establish declaration lineage from verified edit evidence before using names or origin spans to join old/new artifacts. Exact names and equal spans are useful checks, but neither proves continuity after arbitrary source replacement.
3. Require a unique match in both directions, and validate all relevant ancestor contexts. When origins are missing, duplicated or ambiguous, discard the affected mapping rather than choosing a same-label candidate.
4. Resolve old and new symbols separately in each view. The renderer-local IDs and traversal ordering provide no cross-view identity guarantee.
5. Distinguish a verified transformation from a free-form draft. Toolkit can report how it performed a known edit; the current source-apply interface receives replacement text without an edit report. A conservative policy is still needed for arbitrary drafts, deleted/recreated declarations, moved files and changed owners.
6. Recheck source/model/view compatibility after mapping and before accepting positions. A successful source transformation does not prove a complete or renderable view.

The investigation revision deliberately cleared presentations on source application and proposal acceptance. The current [workspace](../../src/lib/workspace/createWorkspace.ts) reconciles compatible positions using the [implemented policy](identity-reconciliation.md). The [version-1 project format](project-format.md) remains unchanged; source inspection alone is still not evidence of application preservation.

## Runtime evidence and remaining work

The [runtime investigation](identity-reconciliation.md) now compares unchanged reparses, Toolkit definition/usage renames, an unrelated-file edit, offset-shifting edits, reordering, insertion, file/owner moves and changed types. It retains Unicode/splice evidence and tests distinct repeated-port contexts in both views. Reordering equal-length usages supplies a concrete same-location identity counterexample. The implementation now adds a conservative draft policy, stale-source/presentation rejection and separate browser preservation/authoring checks through undo/redo and fresh import. General arbitrary-replacement identity and independent layout undo remain gaps. See [verification](../verification.md) for actual application results.
